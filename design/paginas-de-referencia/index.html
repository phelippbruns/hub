Páginas de referência do Hub

41 telas do Hub, retratadas em 2026-11-26 do commit 97d58f3. Existe para servir de ponto de partida a quem for aplicar modo escuro ou trocar o design.

Isto é um retrato, não o app. As imagens são estáticas e as seis páginas em HTML não têm JavaScript: menu não abre, painel não arrasta. Os estados que importam foram capturados como telas próprias. Para a coisa viva, rode o Hub.

O tema não mora aqui. Para escurecer, preencha os valores escuros em docs/design-system/tokens.json e rode npm run tokens: isso acende o Hub inteiro. Depois rode npm run referencia para estas páginas retratarem o novo tema.

MAPA.md tem a mesma informação em texto, para ler de uma vez — é o arquivo a dar para uma IA. mapa.json é a versão de máquina.

O que a troca de tokens não alcança

Quase todo o CSS do Hub é movido por tokens — app/globals.css não tem um único hex. Estes são os pontos que escapam, e que um redesenho precisa tratar à mão:

  • <meta name="theme-color"> sai com o hex literal (#F1EEFF), de app/layout.tsx. Ele pinta a barra do navegador na PWA, e não acompanha o token.
  • 13 atributo(s) style com cor escrita no HTML em design-galeria.html. Cor em atributo não vem de token e não muda com o tema.
  • design/gallery.tsx desenha as amostras com style={{ backgroundColor: value }} e imprime os hex como texto. É documentação da paleta, e por isso não escurece junto.

Telas fora da pasta, e por quê

  • /completar-cadastro — Só é alcançável no retorno do OAuth do Google, que exige um cliente configurado no Google Cloud. Capturar um estado de erro e chamar de tela seria pior do que a ausência.
  • /cabines/convite — O convite é aceito pela lista em /cabines, que é o caminho de quem usa. A rota direta existe para link, e o desenho é o mesmo cartão da lista.
  • /criar-topico e /topico/[id] e /c/<slug>/novo — Redirecionam. Capturar um redirecionamento é capturar o destino com o nome errado.
